# 统一策略接口：回测 / 模拟盘 / 实盘共用一套代码

## 设计目标

策略只写一次。无论跑回测、模拟盘还是实盘，策略拿到的交易接口完全一致：

```python
api.buy()          # 开多 / 加多
api.sell()         # 平多 / 减多
api.sellshort()    # 开空
api.buycover()     # 平空
api.close_all()    # 一键平掉多空
```

策略不关心订单最终如何成交——这个差异由"执行器（Executor）"承担：

```text
                   同一份策略代码（Strategy）
                            │
                     api.buy()/sell()/...
                            │
              ┌─────────────┼─────────────┐
              ▼             ▼             ▼
          回测执行器     模拟盘执行器     实盘执行器
        下一根开盘价    最新价虚拟撮合   币安下单+记账
```

## 三种模式的差异

| 环节 | 回测 | 模拟盘 paper | 实盘 live |
| --- | --- | --- | --- |
| 行情 | 本地 CSV 全量 K 线 | 币安实时滚动窗口 | 币安实时滚动窗口 |
| 策略回调 | 逐根 K 线 `on_bar` | 每次 tick 调一次（当前=最后一根 K 线） | 同左 |
| 下单时机 | 当前收盘产生信号，下一根开盘成交 | 当前最新价即时成交 | 当前最新价即时成交 |
| 账本 | 内存 `TradeAPI` | `AccountLedger` 持久化 | `AccountLedger` 持久化 |
| 真实下单 | 无 | 无 | dry-run 关闭时调用币安 REST |

资金、手续费、滑点、盈亏的计算在三种模式中都走同一套账本规则（`AccountLedger` / `TradeAPI`），结果可直接对比。

## 策略写法（不变）

策略文件放在 `user_data/strategies/*.py`，继承 `Strategy`，二选一实现：

### 事件模式

```python
from quant_api import Strategy

class MyStrategy(Strategy):
    """事件模式示例。"""
    name = "我的策略"
    timeframe = "1h"
    startup_candle_count = 20

    def on_bar(self, api, candles, index):
        """每根 K 线回调一次。"""
        fast = api.sma(5)
        slow = api.sma(20)
        if fast[index - 1] <= slow[index - 1] and fast[index] > slow[index]:
            api.buycover(reason="golden_cover")
            api.buy(ratio=0.95, reason="golden_cross")
        elif fast[index - 1] >= slow[index - 1] and fast[index] < slow[index]:
            api.sell(reason="death_cross")
```

### 信号模式

```python
from quant_api import Strategy

class SignalStrategy(Strategy):
    """信号列模式，参考 freqtrade。"""

    def populate_entry_trend(self, candles, metadata):
        """1=开多，-1=开空，0=无。"""
        return [0] * (len(candles) - 1) + [1]

    def populate_exit_trend(self, candles, metadata):
        """1=平多，-1=平空，0=无。"""
        return [0] * len(candles)
```

两种模式在回测/模拟盘/实盘下都按同一规则解释信号（平仓优先于开仓，避免同根 K 线互相覆盖）。

## 交易接口参考

| 方法 | 说明 | 常用参数 |
| --- | --- | --- |
| `api.buy(price, amount, ratio, reason)` | 开多/加多；不传 amount 时按可用现金 `ratio` 买入 | `ratio` 默认 0.95 |
| `api.sell(price, amount, ratio, reason)` | 平多/减多；默认平全部多头 | `ratio` 默认 1.0 |
| `api.sellshort(price, amount, ratio, reason)` | 开空；按净值 `ratio` 开 | `ratio` 默认 0.5 |
| `api.buycover(price, amount, ratio, reason)` | 平空；默认平全部空头 | `ratio` 默认 1.0 |
| `api.close_all(reason)` | 同时平掉多头和空头 | — |

- `ratio` 必须落在 `(0, 1]`；不合法会被拒绝并记录日志。
- `amount` 指定数量时，仍会按可用现金/持仓裁剪（与回测一致）。
- 所有下单返回 `bool`，表示是否被受理（受资金/持仓/模式约束）。

### 指标与状态

| 接口 | 说明 |
| --- | --- |
| `api.sma(period)` / `api.ema(period)` / `api.rsi(period)` | 仅用当前及之前收盘价计算，防止偷看未来 |
| `api.log(msg)` | 写策略日志，进入 tick 结果 |
| `api.current_price` | 当前价格（实盘/模拟盘为实时价） |
| `api.equity` | 当前账户净值 |
| `api.cash` | 可用现金 |
| `api.position` | 持仓快照（多空数量与成本） |
| `api.current_candle` | 当前 K 线（无窗口时为 None） |

## 做空与实盘现货

- 回测、模拟盘完整支持 `sellshort` / `buycover`。
- 实盘**真实下单**走币安现货，不支持做空：`sellshort` / `buycover` 会被拒绝并在日志记录原因。
- 实盘 `dry_run=True`（默认）时仍可在账本里模拟做空，便于用真实行情验证做空逻辑。
- 因此若策略含做空分支，实盘现货运行时这些分支不会成交——请为实盘准备仅做多版本，或用模拟盘验证做空。

## 内部实现（开发者参考）

代码位于 `backend/app/modules/quant/`：

- `execution/base.py`：`AccountLedger`（账本）、`OrderRequest` / `Fill`（订单与成交）、`RunMode`。
- `execution/api.py`：`StrategyAPI`——策略统一接口，把下单请求交给 `submit` 回调。
- `execution/runner.py`：`run_tick()` 编排"拉行情→跑策略→执行订单→产出结果"；`PaperExecutor` / `LiveExecutor` 是两种执行器。
- `execution/exchange.py`：币安行情（klines）与签名下单（HMAC-SHA256）。
- `runtime/service.py`：实例 CRUD、启停、`RuntimeManager` 轮询与持久化。

新增一种模式只需实现 `Executor`（`execute()` 与 `snapshot()`），策略与 `StrategyAPI` 无需改动。
