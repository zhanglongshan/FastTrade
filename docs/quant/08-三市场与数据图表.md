# 三市场结构与数据图表

侧栏「量化」已拆为三个独立市场目录：**web3-量化**、**量化-A股**、**量化-期货**。三者页面结构一致（数据、数据图表、回测、模拟盘、实盘），共用同一套策略与执行引擎，仅数据目录、数据表和柜台/行情源不同。

## 1. 市场对照

| 维度 | web3-量化 | 量化-A股 | 量化-期货 |
| --- | --- | --- | --- |
| 路由前缀 | `/quant` | `/quant-astock` | `/quant-futures` |
| 数据表前缀 | `quant_web3_*` | `quant_astock_*` | `quant_futures_*` |
| 数据目录 | `user_data/data/binance` | `user_data/data/astock` | `user_data/data/futures` |
| 行情来源 | 币安 REST / 镜像 / 历史归档 | 本地 CSV / XTP 柜台 | 本地 CSV / CTP 柜台 |
| 柜台适配器 | 币安网关 | `xtp`（默认模拟） | `ctp`（默认模拟） |
| 代码格式 | `BTC/USDT` | `600519.SH` | `rb2410.SHFE` |
| 默认做空 | 现货不允许 | 关闭 | 允许 |
| 前端组件 | `module_quant/*` | `module_quant_astock/*` | `module_quant_futures/*` |

三个市场共用策略目录 `user_data/strategies/`。同一份策略（如 `SmaCrossStrategy`）可直接用于 web3 回测、A股回测、期货回测，以及三者的模拟盘/实盘 tick；不再有按市场拆分的策略子目录。

## 2. 数据图表页

三个市场目录均有「数据图表」页：

- web3：`module_quant/chart/index`
- A股：`module_quant_astock/chart/index`
- 期货：`module_quant_futures/chart/index`

操作：选择数据集 → 后端读取本地 CSV → ECharts 绘制 K 线（红涨绿跌）+ 成交量，下方为 OHLCV 明细表。默认只返回最近 2000 根（可通过 `limit` 调整，上限 20000），避免一次传输过大。

后端接口：`GET /quant/data/candles/{dataset_id}`、`GET /quant-astock/candles/{dataset_id}`、`GET /quant-futures/candles/{dataset_id}`。

## 3. A股 / 期货操作流程

以 A股为例（期货把 `quant-astock` 换成 `quant-futures`）：

```bash
# 1) 准备符合列规范的 CSV：date, open, high, low, close, volume
#    放到 user_data/data 下（含子目录均可），页面「数据」tab 会自动列出
# 2) 页面导入，或调用接口：
POST /quant-astock/import
{ "file_path": "user_data/data/600519.csv", "symbol": "600519.SH", "interval": "1d", "source": "local" }

# 3) 回测
POST /quant-astock/backtest
{ "dataset_id": 1, "strategy_name": "SmaCrossStrategy", "initial_cash": 100000 }

# 4) 创建模拟盘实例
POST /quant-astock/live
{ "name": "演示", "mode": "paper", "strategy_name": "SmaCrossStrategy",
  "symbol": "600519.SH", "interval": "1d", "initial_cash": 100000 }

# 5) 运行一次 tick
POST /quant-astock/live/1/tick
{ "reason": "manual" }
```

tick 的行情优先级：**显式 `price` > 显式 `candles_file` > 同代码已导入数据集的 CSV > 柜台适配器 `broker_config.prices`**。因此只要先导入了对应代码的 CSV，页面点「运行一次」即可直接跑通，无需配置柜台价格。

A股/期货接口清单（两个市场各 8 个）：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/datasets` | GET | 数据集列表 |
| `/files` | GET | 可导入的本地 CSV |
| `/import` | POST | 导入 CSV |
| `/candles/{id}` | GET | K 线（图表用） |
| `/backtest` | POST | 执行回测 |
| `/backtests` | GET | 回测记录 |
| `/live` | GET / POST | 实例列表 / 创建 |
| `/live/{id}/tick` | POST | 运行一次 tick |

## 4. 柜台可插拔适配层

`backend/app/modules/quant_market/broker.py` 定义统一接口 `BrokerAdapter`（`connect` / `disconnect` / `latest_price` / `place_order`），当前提供：

- `SimulatedBroker`：默认，用配置的价格本地撮合，不下真实单。
- `XTPBroker` / `CTPBroker`：继承模拟柜台，作为 SDK 接入占位；未装 SDK 时退化为模拟，**不会误发真实报单**。

接入真实 XTP / CTP 时，只需在同一接口下实现真实 SDK 调用并在 `get_broker` 注册，上层策略、回测、模拟盘、实盘代码无需改动。安全约束：密钥类配置不写业务日志，真实下单默认 `dry_run=True` 关闭。

> 当前 XTP/CTP 尚未接入真实 SDK，A股/期货的实盘为模拟撮合。若要接入，需要提供券商/期货 SDK、账号与交易环境。
