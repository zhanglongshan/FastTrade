# 币安 API 密钥配置

本文只讲**币安 API Key / Secret 怎么配、存哪里、怎么轮换**。回测与实例的通用参数见
[06-模拟盘与实盘](./06-模拟盘与实盘.md) 与 [09-执行架构与一致性](./09-执行架构与一致性.md)。

先给结论：

> **币安密钥不写 `backend/env`，只在 Web「模拟盘 / 实盘」实例表单里填写，加密后落库。**
> env 里只放加密主密钥 `DATA_ENCRYPTION_KEY` / `SECRET_KEY` 和环境级配置。

---

## 1. 什么时候需要密钥

| 场景 | 是否需要密钥 | 说明 |
| --- | --- | --- |
| Web 回测 | 否 | 纯本地 CSV，不连交易所 |
| `paper` 模拟盘 | 否 | 用币安**公开**行情（kline / bookTicker），本地虚拟撮合 |
| `live` + `dry_run=true`（默认） | 否 | 用真实行情，但 `LiveExecutor` 不创建下单客户端，不下真单 |
| `live` + `dry_run=false` | **是** | 调用币安 REST 下单、回查、撤单、对账 |

也就是说：**只有关掉 dry-run 的真实实盘才需要 API 密钥**。建议先用 `paper` 和 `dry_run=true`
跑够长时间，再填真实密钥。

---

## 2. 币安侧创建密钥

1. 登录币安网页 → 账户 → **API 管理**，创建一组 API Key。
2. 权限只勾必需项：
   - ✅ **读取**（账户余额、成交、挂单对账要用）
   - ✅ **现货交易**（市价下单；若做 U 本位合约则勾合约权限）
   - ❌ **提币 / 划转 / 其他资金权限**：**不要勾**。本系统没有任何提币逻辑，开了等于给资金开后门。
3. 绑定 **IP 白名单**，填部署服务器的**出口公网 IP**（不是内网 IP）。留空等于任意 IP 可用，风险很高。
4. 保存 API Key 和 API Secret。`Secret` 通常只完整显示一次，丢失只能重建。
5. 确认服务器能访问 `api.binance.com`；网络受限时公开行情可走镜像，但**签名下单不能走镜像**。

> 一组密钥对应一个实例即可，不要多实例共用：共用一个密钥时无法按实例单独撤销权限。

---

## 3. Web 里怎么填

在「量化 → 模拟盘 / 实盘」页点新建实例：

| 字段 | 填写内容 |
| --- | --- |
| `mode` | `live`（真实下单） |
| `dry_run` | **先保持 `true`**；确认策略与下单链路正常后再改 `false` |
| `api_key` | 第 2 步拿到的 API Key（输入框是密码框，不回显） |
| `api_secret` | 对应的 API Secret |
| 其他 | 交易对、周期、资金、费率、杠杆等按策略需要填 |

`paper` 和 `live + dry_run=true` 留空即可。

**当前限制**：前端只有**创建**实例时输入密钥的入口，没有编辑已存在实例密钥的表单。
要更换密钥，需要通过 API 更新实例，或删除实例后重建（删除不会撤销币安侧密钥）。

## 4. 密钥存在哪里（链路）

```
Web 表单（明文）
  → QuantLiveStrategyCreateSchema
  → CryptoUtil.encrypt(明文)          # 加密
  → quant_web3_live_strategy.api_key / api_secret 列（密文）
  → 实例启动 / tick：CryptoUtil.decrypt(密文)   # 内存中的明文
  → LiveExecutor → BinanceOrderClient → HMAC-SHA256 签名 → 币安 REST
```

关键代码位置：

| 环节 | 位置 |
| --- | --- |
| 创建时加密 | `app/modules/quant/runtime/service.py` `create_live_strategy()` |
| 更新时处理 | 同文件 `update_live_strategy()`：空字符串 = 清空密钥，留空（`None`）= 不改 |
| 响应脱敏 | `to_schema()` 只输出 `has_api_key: bool`，**从不出明文** |
| 运行时解密 | `_build_executor()`：`CryptoUtil.decrypt(...)` |
| 签名与请求 | `app/modules/quant/execution/exchange.py` `BinanceOrderClient._sign()` |

签名方式是币安标准的 `HMAC-SHA256(api_secret, urlencode(params))`，请求头带 `X-MBX-APIKEY`，
参数含毫秒 `timestamp` 与 `recvWindow=5000`。日志只记录状态码和简短原因，**不记录密钥或签名**。

## 5. 加密主密钥怎么配（env 部分）

`backend/env/.env.dev` / `.env.prod` 里只需要关心这三个值：

```ini
# 令牌签名密钥，生产必须改；DATA_ENCRYPTION_KEY 留空时还会用它派生加密主密钥
SECRET_KEY = change_me_generate_with_openssl_rand_hex_32

# 专门加密落库敏感数据（含币安密钥），推荐显式设置， openssl rand -hex 32
DATA_ENCRYPTION_KEY = ''

# 旧主密钥列表（逗号分隔），仅用于解密历史密文
DATA_ENCRYPTION_OLD_KEYS = ''
```

生成方式：

```bash
openssl rand -hex 32
```

要点：

- 留空 `DATA_ENCRYPTION_KEY` 时，系统用 `SECRET_KEY` 经 HKDF 派生主密钥，功能可用，但**两个密钥的用途耦合**，不建议生产这么做。
- 加密始终用**主密钥**（`DATA_ENCRYPTION_KEY` 或 `SECRET_KEY`）；解密会依次尝试主密钥、
  `DATA_ENCRYPTION_OLD_KEYS` 里的每个旧密钥，以及兼容历史版本的旧派生方式。
- **轮换主密钥的正确顺序**：把旧值填进 `DATA_ENCRYPTION_OLD_KEYS` → 设置新 `DATA_ENCRYPTION_KEY` → 重启。
  直接改主密钥而不保留旧值，会导致已存的所有币安密钥解密失败，实盘实例启动即报错。
- 这些文件已由根 `.gitignore` 的 `backend/env/*` 忽略，只有 `*.example` 模板可提交。

模板：[`backend/env/.env.quant.example`](../../backend/env/.env.quant.example)。

## 6. 检查清单

上线前逐项确认：

- [ ] 币安密钥只有「读取 + 交易」权限，**没有提币权限**
- [ ] 已绑定服务器出口 IP 白名单
- [ ] 密钥只填在 Web 实例表单，**没有出现在 `.env`、代码、日志或聊天记录里**
- [ ] `DATA_ENCRYPTION_KEY` 已显式设置，并妥善备份（备份本身也要加密保存）
- [ ] 先用 `dry_run=true` 跑通，确认成交流水、对账、日志正常
- [ ] 已执行数据库迁移（`uv run main.py upgrade --env=dev`）
- [ ] 真实下单前把 `leverage` 保持 1、现货实例 `allow_short=false`

## 7. 常见问题

**Q：实例列表看不到密钥，是不是没存上？**
A：列表只返回 `has_api_key` 布尔标志，明文不出库，这是设计。只要创建时提示成功即可。

**Q：改了 `SECRET_KEY` 后实盘报「敏感数据解密失败」？**
A：说明没有保留旧密钥。把旧 `SECRET_KEY` 或旧 `DATA_ENCRYPTION_KEY` 填进
`DATA_ENCRYPTION_OLD_KEYS`，重启后即可解密历史实例；若旧值也已丢失，只能删掉实例重建并重新填密钥。

**Q：更新实例时把 api_key 输入框清空会怎样？**
A：更新接口里**空字符串表示清空密钥**，`null` / 字段不传才表示不改。当前前端没有编辑密钥的表单，
通过 API 调用时务必注意这个区别。

**Q：dry-run 模式下为什么不需要密钥？**
A：`LiveExecutor` 只在 `dry_run=False` 时构造下单客户端；dry-run 仅用公开行情做本地撮合。

**Q：密钥能放在环境变量里吗？**
A：不建议。当前实现是从实例表单加密落库，env 里没有读取币安密钥的入口；放进去既不会被使用，
又增加泄露面。env 只放加密主密钥等环境级配置。
