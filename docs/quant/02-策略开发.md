# 02 策略开发

策略放在项目根目录 `user_data/strategies/` 下，任意 `.py` 文件，系统会**自动发现**其中继承 `Strategy` 并实现交易逻辑的类。文件名下划线开头（如 `_helper.py`）会被忽略。

## 1. 两种策略模式

| 模式 | 需要实现 | 适合场景 |
| --- | --- | --- |
| `event` 事件模式 | `on_bar(api, candles, index)` | 需要逐根 K 线维护状态、直接使用 `api.buy()` 等接口 |
| `signal` 信号模式 | `populate_entry_trend()` / `populate_exit_trend()` | 参考 freqtrade 的信号列写法，向量化思维 |

系统根据是否覆盖这些方法自动判断模式，页面与 API 会展示该模式。

## 2. 交易 API

在事件模式中，策略通过 `api` 参数下单：

| 方法 | 作用 | 关键参数 |
| --- | --- | --- |
| `api.buy()` | 开多/加多 | `price`、`amount`、`ratio`（默认 0.95）、`reason` |
| `api.sell()` | 平多/减多 | `amount`、`ratio`（默认 1.0）、`reason` |
| `api.sellshort()` | 开空 | `ratio`（默认 0.5）、`reason` |
| `api.buycover()` | 平空 | `ratio`（默认 1.0）、`reason` |
| `api.close_all()` | 同时平多与空 | `reason` |
| `api.log()` | 写策略日志 | 字符串 |

辅助属性与方法：

- `api.current_price`：当前收盘价
- `api.cash`、`api.equity`：现金与净值
- `api.position`：`long_qty` / `short_qty` / 持仓均价
- `api.sma(period)` / `api.ema(period)` / `api.rsi(period)`：仅使用当前及之前 K 线的指标序列
- `api.current_candle`：当前 K 线
- `api.candles`：完整 K 线列表（**不要访问 index 之后的数据**）

### 成交规则

- 策略在**当前 K 线收盘**产生订单，系统在**下一根 K 线开盘**撮合。
- 最后一根 K 线产生的订单按最后收盘价撮合，避免悬挂订单。
- 手续费按单边 `fee_rate` 收取，滑点按 `slippage` 计入成交价。
- 做多：买入扣现金，卖出回现金；做空：开空收到现金，平空支付现金，净值 = 现金 + 多头市值 - 空头市值。

## 3. 事件模式示例

文件：`user_data/strategies/sma_cross_strategy.py`

```python
from quant_api import Strategy


class SmaCrossStrategy(Strategy):
    """5/20 均线交叉：金叉开多，死叉平多。"""

    name = "SMA均线交叉"
    timeframe = "1h"
    startup_candle_count = 20

    def on_bar(self, api, candles, index):
        fast = api.sma(5)
        slow = api.sma(20)
        if index < self.startup_candle_count:
            return
        values = [fast[index - 1], fast[index], slow[index - 1], slow[index]]
        if any(value is None for value in values):
            return

        fast_prev, fast_now, slow_prev, slow_now = values
        if fast_prev <= slow_prev and fast_now > slow_now:
            api.buycover(reason="golden_cross_cover")
            api.buy(ratio=0.95, reason="golden_cross")
        elif fast_prev >= slow_prev and fast_now < slow_now:
            api.sell(reason="death_cross")
```

## 4. 信号模式示例

文件：`user_data/strategies/rsi_signal_strategy.py`

```python
from quant_api import Strategy, rsi


class RsiSignalStrategy(Strategy):
    """RSI 超卖开多、超买平多。"""

    name = "RSI超卖反弹"
    timeframe = "1h"
    startup_candle_count = 14

    def populate_entry_trend(self, candles, metadata):
        values = rsi([c.close for c in candles], 14)
        signals = [0] * len(candles)
        if values and values[-1] is not None and values[-1] < 30:
            signals[-1] = 1
        return signals

    def populate_exit_trend(self, candles, metadata):
        values = rsi([c.close for c in candles], 14)
        signals = [0] * len(candles)
        if values and values[-1] is not None and values[-1] > 70:
            signals[-1] = 1
        return signals
```

信号约定：

- 开仓：`1` 开多，`-1` 开空，`0` 无
- 平仓：`1` 平多，`-1` 平空，`0` 无
- 引擎只读取**当前下标**的信号，不会读取未来位置

## 5. 策略属性

| 属性 | 说明 |
| --- | --- |
| `name` | 策略展示名；未设置时使用类名 |
| `timeframe` | 推荐周期，仅作提示，不强制匹配数据集 |
| `startup_candle_count` | 预热 K 线数；该数量之前不会调用交易逻辑 |

## 6. 导入方式

策略文件可直接写：

```python
from quant_api import Strategy, rsi
```

`quant_api` 是系统注入的模块别名，指向 `backend/app/modules/quant/strategy/api.py`。也可使用完整路径：

```python
from app.modules.quant.strategy.api import Strategy
```

## 7. 调试建议

- 先用小时间范围数据验证策略，避免一次回测过慢。
- 用 `api.log()` 记录关键判断，日志会保存在回测结果中并在页面展示。
- 策略代码在服务端执行，等同于受信任代码；不要加载来源不明的策略文件。
- 修改策略文件后无需重启后端，刷新策略列表或重新执行回测即可重新加载。
