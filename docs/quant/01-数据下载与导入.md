# 01 数据下载与导入

量化数据统一保存为标准 OHLCV CSV，列为 `date,open,high,low,close,volume`，`date` 为 UTC ISO8601。
下载与导入都会按 `date` 去重合并并登记到「已登记数据集」，回测/模拟盘/实盘直接复用这些文件。

## 下载方式总览

| 方式 | `source` | 数据源 | 支持市场 | 适用场景 |
| --- | --- | --- | --- | --- |
| 官方 REST | `api`（默认） | `api.binance.com` / `fapi.binance.com` | 现货、U 本位合约 | 近期数据、需要实时性 |
| 公开 REST 镜像 | `mirror` | `data-api.binance.vision` | 仅现货 | 官方 API 受限/超时的网络环境 |
| 历史归档 | `archive` | `data.binance.vision` 月/日 ZIP | 现货、U 本位合约 | 长历史、大跨度回测数据 |

三种方式最终产出完全一致的 CSV 格式，可以混用、互补：先用归档拉长历史，再用 `api`/`mirror` 增量更新近端。

### 归档方式的实现要点

参考 freqtrade 的 `binance_mirror.py` / `binance_public_data.py`：

- **整月用月文件、残缺月用日文件**：例如请求 `2024-01-01 ~ 2024-03-16`，会下载 `2024-01`、`2024-02` 两个月 ZIP 加 3 月 1—16 日的日 ZIP，多年历史也只需月度数量级的请求。
- **时间戳按位数归一**：现货归档多为微秒、合约多为毫秒、老文件可能是秒，按数字长度判断单位后统一转为毫秒。
- **表头智能识别**：现货归档无表头、合约归档有表头，通过首字符是否为数字判断。
- **并发与重试**：归档 ZIP 最多 8 个并发；404 视为该片段无数据并记录在 `missing_periods`，其他瞬时错误指数退避重试 3 次。
- **近端补齐**：归档有约 2 天延迟，默认自动用公开镜像补齐归档末端到结束时间的数据；不需要时设 `fill_recent: false` / `--no-fill-recent`。

## 方式一：页面下载（推荐）

1. 启动后端与前端，登录管理台，进入 **量化 → 下载**。
2. 在「下载币安数据」卡片填写：

   - **交易对**：如 `BTC/USDT` 或 `BTCUSDT`（自动规范化）。
   - **周期**：`1m/3m/5m/15m/30m/1h/2h/4h/6h/8h/12h/1d/3d/1w/1M`。
   - **方式**：现货 REST / 公开镜像 / 历史归档。
   - **市场**：现货或 U 本位合约；选「公开镜像」时会自动锁定为现货。
   - **起止日期**：留空时下载最近 30 天至当前时间；纯日期的结束日按当天 23:59:59 处理。
   - **最近天数**：填写后优先于起止日期，从当前时间往前推 N 天。
   - **清空重下**：勾选后忽略本地已有数据，直接覆盖写入。

3. 点击 **下载**。完成后显示写入路径、本次下载条数、合并后总条数；归档方式还会显示归档文件数与缺失片段警告。
4. 下方「已登记数据集」表会新增或更新记录。

## 方式二：命令行下载

在 `backend/` 目录执行（`mingling` 为兼容别名）：

```bash
cd backend

# 官方 REST：现货，最近 30 天
uv run python main.py quant download -s BTC/USDT -i 1h

# 官方 REST：U 本位合约，指定历史区间
uv run python main.py quant download -s BTC/USDT -i 4h \
  --market futures --start 2024-01-01 --end 2024-06-30

# 公开镜像：仅现货，最近 7 天
uv run python main.py quant download -s ETH/USDT -i 1h \
  --source mirror --days 7

# 历史归档：整段长历史
uv run python main.py quant download -s BTC/USDT -i 1h \
  --source archive --start 2020-01-01 --end 2023-12-31

# 归档快捷命令（等价 --source archive）
uv run python main.py quant download-archive -s BTC/USDT -i 1h \
  --start 2024-01-01 --end 2024-12-31 --market futures
```

`download` 参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `--symbol` / `-s` | 是 | 交易对，如 `BTC/USDT` |
| `--interval` / `-i` | 是 | K 线周期 |
| `--source` | 否 | `api`（默认）/ `mirror` / `archive` |
| `--market` | 否 | `spot`（默认）/ `futures` |
| `--start` / `--end` | 否 | 起止日期 `YYYY-MM-DD` |
| `--days` | 否 | 最近 N 天，优先于起止日期 |
| `--erase` | 否 | 清空本地已有数据后重新下载 |
| `--fill-recent` / `--no-fill-recent` | 否 | 归档是否补齐近端，默认补齐 |
| `--limit` | 否 | REST 单页条数，默认/上限 1000 |
| `--env` | 否 | 运行环境，默认 `dev` |

输出为 JSON，包含 `file_path`、`downloaded`、`row_count`、`dataset_id`、`source`、`market`、`requests`、`archive_files`、`missing_periods`、`warnings`。

## 方式三：导入本地 CSV

CSV 必须包含表头：

```csv
date,open,high,low,close,volume
2024-01-01T00:00:00+00:00,42000,42500,41800,42300,1200
```

`date` 支持 ISO8601（推荐带时区）；数值列必须是数字。

### 页面导入

进入 **量化 → 下载**，在「导入本地 CSV」中选择文件、填写交易对与周期后点击 **导入**。
可导入目录由后端限制为 `user_data/data/` 与 `backend/data/quant/`，路径穿越（`../`）会被拒绝。

### 命令行导入

```bash
cd backend
uv run python main.py quant import user_data/data/my_data.csv \
  --symbol BTC/USDT --interval 1h --source local
```

导入后文件归一化写入 `user_data/data/local_BTCUSDT_1h.csv`。

## 数据文件与命名

```text
user_data/data/binance/BTCUSDT_1h.csv              # 现货：api / mirror / archive 共用
user_data/data/binance/futures/BTCUSDT_1h.csv      # U 本位合约
```

数据集 `name` 为 `binance_{交易对}_{周期}`（合约加 `futures_` 前缀），例如 `binance_btcusdt_1h`。
不同来源下载同一交易对与周期时共用同一 CSV，按 `date` 去重合并；需要完全重下时勾选「清空重下」或加 `--erase`。

## 常见问题

- **归档提示"至少延迟 2 天"**：归档请求范围全部落在最近 2 天内，请改用 `api`/`mirror`，或把结束时间提前。
- **归档历史缺失片段**：`missing_periods` 会列出无数据的月/日；通常是该币种尚未上市，属正常现象。
- **公开镜像仅支持现货**：合约请使用 `--market futures --source api` 或 `--source archive`。
- **币安返回 451/限制访问**：检查网络出口；可换 `mirror` 或 `archive` 通道，请求会重试 3 次。
- **CSV 缺少必需列**：按上方表头补齐，列名区分大小写。
- **导入提示文件不在允许目录**：把文件复制到 `user_data/data/` 后重试。
