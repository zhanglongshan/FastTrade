# 模拟盘与实盘操作文档

模拟盘（paper）与实盘（live）在 **量化** 侧栏下各有一个页面，共用同一套策略、同一个交易接口、同一套执行引擎；区别只在"订单如何成交"：

| 维度 | 回测 | 模拟盘 paper | 实盘 live |
| --- | --- | --- | --- |
| 行情来源 | 本地 CSV | 币安 WebSocket（不可用时 REST 兜底）| 币安 WebSocket（不可用时 REST 兜底）|
| 资金 | 初始资金参数 | 虚拟资金 | 真实/模拟（看 dry_run） |
| 撮合 | 下一根开盘价 | 下一根开盘价（含盘口深度上限）| 交易所真实成交（回查确认）|
| 驱动 | 一次性跑完 | K 线收盘事件驱动 | K 线收盘事件驱动 |
| 做空 | 支持 | 支持 | 现货不支持（真实模式拒绝） |

一句话原则：**先在回测验证，再在模拟盘跟真实行情跑，最后才考虑实盘**。

> 三种模式策略代码完全相同，见 [07-统一策略接口](./07-统一策略接口.md)。

## 1. 前置条件

- 后端服务正常运行（`python main.py run --env=dev`），依赖 Redis 与 PostgreSQL。
- 币安公开行情接口可达（拉取最新 K 线用）。若网络受限，可用 CLI 的 `--data-file` 用本地 CSV 离线驱动一次（见第 4 节）。
- 已有至少一张数据集或一个策略；策略放在 `user_data/strategies/`。

## 2. 页面操作（推荐）

### 2.1 创建实例

进入「量化 → 模拟盘」或「量化 → 实盘」页面，填写：

- **实例名称**：如 `BTC-1h-SMA`。
- **策略**：下拉选择自动发现的策略（与回测页面同一批）。
- **交易对**：如 `BTC/USDT`。
- **周期**：如 `1h`，决定 K 线收盘事件的周期（1m→每分钟一次，1h→每小时一次）。
- **初始资金 / 手续费率 / 滑点**：虚拟或记账参数。
- **做空**：模拟盘可开；实盘现货建议关闭。
- **dry-run**（仅实盘）：默认开启 = 只模拟不下单。关闭后需要填写币安 API Key/Secret 才会真实下单。

提交后实例出现在下方列表，状态为"已停止"。

### 2.2 启动 / 停止 / 手动运行

- **启动**：开启常驻任务，后端订阅行情并在每根 K 线收盘时运行策略（进程内任务，服务重启后会自动恢复运行中的实例）。
- **停止**：暂停任务并退订行情。
- **运行一次**：立即拉取最新行情运行一次 tick，不等待收盘事件，适合快速验证。
- **详情**：查看账户净值、现金、持仓、已实现盈亏、最近 tick 日志与成交流水。
- **删除**：先停止任务再软删除实例。

### 2.3 实盘安全须知

1. 实盘实例**默认 dry-run**。页面顶部有红色风险提示，创建时若不填密钥即便关闭 dry-run 也不会真实下单（会在 tick 日志记录失败）。
2. 密钥加密存储（Fernet），接口只返回 `has_api_key` 布尔值，永不回传明文。
3. 币安 API Key 建议只授予"现货交易"权限，**不要开启提现**。
4. 现货模式不支持做空：`sellshort` / `buycover` 在真实下单时会被拒绝并记录日志。
5. 先用模拟盘充分验证策略，再考虑小额实盘。

## 3. 行情驱动与执行保障

### 3.1 事件驱动：用推送替代轮询

后端通过 `RuntimeManager` 为每个运行中的实例维护一个 asyncio 任务，行情来自进程内共享的
`MarketStream`（`execution/stream.py`），一个 WebSocket 连接承载所有实例的订阅：

| 订阅 | 用途 |
| --- | --- |
| `<symbol>@kline_<周期>` | 在 K 线**收盘瞬间**唤醒 tick，替代 `sleep(周期)` |
| `<symbol>@bookTicker` | 最优买卖价与挂单量（L1 盘口），用于深度约束与成交价兜底 |

- 订阅按 `(交易对, 周期)` 引用计数，最后一个使用者退订才真正 `UNSUBSCRIBE`。
- 首次订阅与断线重连后用 REST 回补历史；发现缺根（`open_time` 不连续）会限流回补。
- 周期大于 1 分钟的实例额外订阅 `1m`，在每根 1 分钟收盘做一次**风控专检**（只判止损/熔断，
  不跑策略），把止损发现延迟从一根大周期缩短到 1 分钟。风控心跳使用**独立占位**
  （进程内 30 秒节流），不写 `last_tick_time`，因此既不会被信号周期的"半根 K 线窗"挡掉，
  也不会把真正的信号 tick 误判成"本根已处理"。
- **WebSocket 不可用（网络受限）时自动退回 REST 轮询**：等待超时会按原来的 bar 对齐方式
  拉取行情跑一次 tick，功能不缺失（代价是恢复秒级延迟）。

每次 tick 的账本快照、最近结果、错误与成交会落库（`quant_live_strategy`、`quant_trade_record`）。

### 3.2 成交口径：与回测完全一致

回测语义是"第 N 根收盘出信号、第 N+1 根开盘成交"，实盘复刻方式：

1. 信号窗口只使用**已收盘** K 线（形成中的那根丢弃）；
2. 成交价取新一根的**开盘价**（推送已到达时），未到达时用盘口中间价近似，绝不用信号 bar 的收盘价；
3. 按比例开仓的数量在**成交价**上重算，而不是按信号价预估。

为避免"近似"被误当成"精确"，每次 tick 的成交价口径都会记入 `last_result.fill_basis`：

| `fill_basis` | 含义 | 是否已计入点差 |
| --- | --- | --- |
| `next_open` | 新一根 K 线的真实开盘价 | 不需要（开盘价本身可成交） |
| `mid_fallback` | 新 bar 尚未推送，用盘口中间价近似 | 是，买入加半价差、卖出减半价差 |
| `bar_close` | REST 兜底且末根已收盘（仅风控路径可能出现） | 否 |
| `stale` | 行情未刷新到下一根，本轮不产生信号 | — |
| `risk_only` | 1 分钟风控专检 | — |

> 若长期看到 `mid_fallback`，说明行情推送延迟偏大（通常是网络或交易所推送抖动），
> 此时成交价会围绕真实开盘价上下浮动，绩效对比应把这部分噪声考虑进去。

### 3.2.1 止损的成交价口径

模拟盘/实盘只能在 K 线收盘后发现破位，然后按**当时的市价**下市价单，因此止损成交价就是
当前价，而不是止损触发价。回测仍按"止损价与开盘价中更差者"记账（等价于交易所侧止损单）。
两者都在成交记录里带 `reason=stop_loss`，可直接对照。

### 3.3 深度约束：模拟盘不再"无限量"成交

`bookTicker` 的买一/卖一量作为成交量上限：买入受卖一量限制、卖出受买一量限制。
盘口缺失或超过 10 秒未更新时不做限制（视为无约束）。

被裁掉的差额不再静默丢弃：

- 记入本次 tick 的 `unfilled[]`（`reason=depth`），页面与流水都能看到"本应成交多少、实际成交多少"；
- **模拟盘**把差额放进账本的待补队列，下一次 tick 按当时价格继续撮合，补不上则记
  `reason=depth_retry_failed` 后放弃（队列上限 5 笔）；
- **实盘**只记录不补发，避免凭空再发一张市价单造成双倍仓位。

### 3.4 实盘下单：回查 + 撤单 + 真实手续费

真实下单（`dry_run=false`）的完整流程：

1. 按 `MARKET_LOT_SIZE` / `LOT_SIZE` 规整数量，按 `PRICE_FILTER` 规整价格；
2. 本地预校验 `minQty` / `maxQty` / `minNotional` / `maxNotional`，不通过直接拒绝并记录原因；
3. 下单后 `GET /api/v3/order` **轮询回查**（默认 8 秒），拿到真实 `executedQty` 与成交额；
4. 超时仍未终态则 `DELETE /api/v3/order` 撤单，再回查一次；完全未成交则本次不记账；
5. 手续费优先取响应 `fills[].commission`（计价币），缺失时查 `/api/v3/myTrades` 回填，
   仍不可信（如以 BNB 计费）时退回配置费率；账本按真实手续费扣减。

### 3.5 多实例与对账

- **行锁占位**：每次 tick 先 `SELECT ... FOR UPDATE` 锁住实例行，判断"距上次 tick 是否不足
  半根 K 线"，是则判定本根已由其他副本处理并跳过。锁只在读-判-写这段持有，不跨越下单网络 IO。
  进程内仍保留每实例一把 asyncio 锁，两层共同防止同一信号重复下单。
- **对账**（真实实盘，默认 30 秒节流）：
  - 现金、多头持仓以交易所余额覆盖；现货模式下账本中残留的空头强制清零；
  - 用 `/api/v3/myTrades` 复算累计手续费与已实现盈亏（成交窗口被截断时只校正余额，不校正盈亏）；
  - `/api/v3/openOrders` 中存活超过 60 秒的孤儿挂单自动撤销并记录告警。

## 4. 命令行操作

```bash
cd backend

# 创建模拟盘实例
python main.py quant live-create --name BTC-1h-SMA \
  --strategy SmaCrossStrategy --symbol BTC/USDT --interval 1h \
  --mode paper --cash 10000 --env=dev

# 创建实盘实例（dry-run，不下真实单；真实下单再加 --no-dry-run 与密钥）
python main.py quant live-create --name BTC-live \
  --strategy SmaCrossStrategy --symbol BTC/USDT --interval 1h \
  --mode live --dry-run --env=dev

# 列出实例（可按 --mode paper/live 过滤）
python main.py quant live-list --env=dev
python main.py quant live-list --mode paper --env=dev

# 手动运行一次 tick（在线拉行情）
python main.py quant live-tick 1 --env=dev

# 离线验证：用本地 CSV 驱动一次 tick（不请求币安）
python main.py quant live-tick 1 --data-file user_data/data/binance/BTCUSDT_1h.csv --env=dev

# 启动 / 停止轮询（CLI 进程内生效；常驻运行请用页面或保持服务进程）
python main.py quant live-start 1 --env=dev
python main.py quant live-stop 1 --env=dev
```

> `--data-file` 用于离线验证、回归测试或网络受限场景；CSV 需符合 `date,open,high,low,close,volume` 列规范。

## 5. API 速查

统一前缀 `/api/v1/quant/live`：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/create` | 创建实例 |
| GET | `/list?mode=paper\|live` | 实例列表 |
| GET | `/detail/{id}` | 实例详情（不含密钥） |
| PUT | `/update/{id}` | 更新费率/滑点/dry_run/密钥等 |
| POST | `/start/{id}` | 启动轮询 |
| POST | `/stop/{id}` | 停止轮询 |
| POST | `/tick/{id}` | 手动运行一次 |
| GET | `/trades/{id}` | 成交流水 |
| DELETE | `/delete/{id}` | 删除实例 |

完整字段见 [05-API参考](./05-API参考.md) 与源码 `runtime/schema`。

## 6. 数据库

- `quant_live_strategy`：实例配置、加密密钥、账户账本快照、最近结果与错误。
- `quant_trade_record`：每次 tick 产生的成交（方向、数量、价格、手续费、盈亏、原因、时间）。

均由 Alembic 迁移 `52f69779bd83` 创建。旧库升级执行 `python main.py upgrade --env=dev` 或随服务启动自动迁移。
