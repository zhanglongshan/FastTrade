# 三市场交易所密钥与持仓管理

web3（币安）、量化-A股（中泰 XTP）、量化-期货（CTP）三个市场目录都新增了
**交易所密钥管理**与**持仓管理**页面。三市场共用一套后端模型与服务，通过 `market` 字段隔离数据。

## 1. 页面与路径

| 市场 | 菜单路径 | 组件目录 | API 前缀 |
| --- | --- | --- | --- |
| Web3 量化 | web3-量化-密钥 / web3-量化-持仓 | `module_quant/key`、`module_quant/position` | `/quant` |
| 量化-A股 | 量化-A股-key / 量化-A股-position | `module_quant_astock/key`、`position` | `/quant-astock` |
| 量化-期货 | 量化-期货-key / 量化-期货-position | `module_quant_futures/key`、`position` | `/quant-futures` |

前端通用组件放在 `front-web/src/views/module_quant/components/`：

- `ExchangeKeyPanel.vue`：密钥列表、新增、编辑、删除
- `PositionPanel.vue`：持仓列表、新增、编辑、删除

六个页面的 `index.vue` 只是薄封装，传入 `apiPath` / `broker` / `label`。
新增或修改页面后，既有数据库需要执行一次幂等菜单同步：

```bash
cd backend
uv run main.py quant init-menu --env=dev
```

## 2. 密钥管理

### 2.1 字段

| 字段 | 说明 |
| --- | --- |
| `name` | 密钥名称，同市场内唯一 |
| `broker` | 柜台类型，由市场决定：web3=`binance`、A股=`xtp`、期货=`ctp`。传错返回 422 |
| `api_key` / `api_secret` | 明文只在提交时出现，经 `CryptoUtil.encrypt()` 加密后落库 |
| `extra_config` | 非敏感扩展配置 JSON，例如 CTP 的交易/行情地址；**不要放密钥** |
| `status` | 0 停用、1 启用 |

### 2.2 安全约定

- 列表和详情只返回 `has_api_key` / `has_api_secret` 布尔标志，**任何接口都不回显明文**；
- 更新时**不传密钥字段**（或传 `null`）表示保留原值，**传空字符串表示清空**；
- 数据库列 `api_key` / `api_secret` 存的是密文，直接查库也看不到明文；
- 更换加密主密钥必须先把旧值放进 `DATA_ENCRYPTION_OLD_KEYS`，详见
  [10-币安密钥配置](./10-币安密钥配置.md)。

> 这里的密钥是**独立管理的交易所凭据**，与「实时策略实例」表单里的币安密钥是两处存储：
> 实例表单的密钥直接被 `_build_executor()` 用于真实下单；本页的密钥作为集中登记，
> 供后续实例引用或多柜台扩展使用。目前两者尚未自动打通，配置真实实盘仍需在实例表单填写密钥。

### 2.3 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/{prefix}/keys` | 列表（脱敏） |
| POST | `/{prefix}/keys` | 新增 |
| PATCH | `/{prefix}/keys/{id}` | 更新 |
| DELETE | `/{prefix}/keys/{id}` | 删除 |

## 3. 持仓管理

| 字段 | 说明 |
| --- | --- |
| `symbol` | 交易标的，如 `BTC/USDT`、`600519.SH`、`rb2410.SHFE` |
| `direction` | `long` 多头 / `short` 空头 |
| `qty` | 持仓数量，必须 > 0 |
| `avg_price` | 持仓均价，不能为负 |
| `status` | 0 已平、1 持有 |
| `description` | 备注 |

同市场内「标的 + 方向」唯一，避免同一持仓被重复登记。

API 与密钥同构：`GET/POST /{prefix}/positions`、`PATCH/DELETE /{prefix}/positions/{id}`。

> 此处的持仓是**手动登记或校正的快照**，不直接改写实时策略实例的账本（`account` 快照仍由
> tick 驱动）。它适合用来记录外部持仓、初始仓位，或在对账后保留一份人工确认的记录。

## 4. 数据与权限

- 两张表：`quant_exchange_key`、`quant_position`，均带 `market` 字段与对应索引；
- 所有查询强制带 `market` 条件，三市场数据互不可见；
- 权限码按市场区分：`module_quant:{key,position}:{query,create,update,delete}`、
  `module_quant_astock:*`、`module_quant_futures:*`；
- 迁移文件：`backend/app/alembic/versions/2026_11_19_2246_e46ebdd56ed6.py`
  （上游 `a7c3e1b9f204`），部署时执行 `uv run main.py upgrade --env=dev`。
