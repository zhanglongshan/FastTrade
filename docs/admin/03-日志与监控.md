# 03 日志与监控

## 日志管理（/system/log）

两类日志**物理分表**：`sys_login_log`（登录日志）与 `sys_operation_log`（操作日志），页面双 Tab 对应展示。

### 登录日志

写入方：`auth/service.py::_write_login_log`（登录成功与失败路径都写，写入失败只告警不影响主流程）。

| 字段 | 说明 |
| --- | --- |
| username | 登录账号 |
| status | **1=成功 2=失败**（注意与通用 0/1 语义不同） |
| login_ip / login_location | IP 与归属地（ip2region 本地离线库，参数 `ip_location_enable` 开关） |
| request_os / request_browser | 操作系统 / 浏览器 UA 解析 |
| msg | 提示消息（如失败原因） |
| 登录时间 | created_time |

页面操作：查询（用户名 like、登录状态、登录时间段）、详情、删除/批量删除；**登录日志无导出**、无「清空」按钮；IP 可点击反查操作日志、复制。

权限码：`module_system:login_log:query` / `module_system:login_log:delete`。

### 操作日志

采集方：`OperationLogRoute` 路由类（`app/core/router_class.py`），挂在该路由类上的接口**自动记录**，无需业务代码打点，后台任务异步落库。

| 字段 | 说明 |
| --- | --- |
| username | 操作人（从 `request.state.ctx` 取，取不到为 unknown） |
| request_path / request_method | 请求路径与方法 |
| request_payload | 请求体；**超 2000 字截断为「请求参数过长」** |
| response_code / response_json | 响应状态码与响应体 |
| process_time | 耗时（如 `0.12s`） |
| description | 路由 summary |
| request_ip | 请求 IP |

**敏感脱敏**：请求体/响应体对敏感键（password、token、authorization、api_key、secret 等，递归匹配）一律替换为 `******` 后入库，避免 token/密码明文落库；form 表单自动过滤 UploadFile 对象。记录范围受配置 `OPERATION_RECORD_METHOD` 控制（默认含写操作类请求）。

页面操作：查询（请求路径、请求 IP）、详情、删除/批量删除、**导出 xlsx**（`operation_log.xlsx`，仅操作日志支持导出）。

权限码：`module_system:log:query/detail/export/delete`。

### 日志清理

页面无「清空日志」按钮；清理走任务系统内置处理器 `cleanup_expired_logs(days=90)`（默认保留 90 天），用 `DELETE` **物理删除**两类表中 `created_time < cutoff` 的记录，返回各表删除条数。通过 **任务管理 → 定时任务 → 节点管理** 配置内置函数型节点 `builtin:system_log.cleanup_expired_logs` 定时执行（`args=90`），见 [04-定时任务与存储](./04-定时任务与存储.md)。

## 在线用户（/monitor/online）

来自 Redis 会话（`user_session:*` 键，见 [01-登录与个性化](./01-登录与个性化.md)），非数据库表。

- 列表字段：session_id、登录类型、IP（可复制）、用户名、账号、登录位置、OS、登录时间；按 IP/用户名/登录位置筛选。
- 操作：**强退单个会话**、**强退所有在线用户**；强退后该用户下一次请求即被判定失效重新登录。
- 另有「当前用户在线会话」（仅登录态自查）与「仪表盘统计」（在线用户数/总用户数/今日登录/登录趋势/最近登录）。
- 权限码：`module_monitor:online:query` / `module_monitor:online:delete`（强退+强退所有）；仪表盘 `module_monitor:dashboard:query`。

## 服务器监控（/monitor/server）

`GET /monitor/server/info`（权限 `module_monitor:server:query`），psutil 采样放工作线程（`asyncio.to_thread`，网络盘/卸载挂载点可能秒级阻塞）。

| 分组 | 指标 |
| --- | --- |
| CPU | 核心数、用户使用率 used、系统使用率 sys、空闲率 free（环形进度 + 图例：<60% 正常 / 60-80% 警告 / >80% 危险） |
| 内存 | 总量/已用/空闲/使用率 |
| 磁盘 | 挂载路径、文件系统类型、总容量/已用/可用、使用率（无权限/不存在的挂载点跳过） |
| Python 进程 | 名称、版本、启动时间、运行时长（X天X小时X分钟）、安装路径、进程内存占用/使用率 |
| 系统信息 | IP（UDP 路由探测降级链）、主机名、架构、系统、项目目录（cwd） |

页面未展示网络指标（schema 无 network 字段）。

## 缓存监控（/monitor/cache）

「监控信息」Tab：Redis 版本、运行模式（单机/集群）、端口、客户端数、运行天数、使用内存、CPU、maxmemory、AOF、RDB 状态、Key 总数、网络 IO（瞬时 kbps）；ECharts 展示命令统计（COMMANDSTATS 环形图）与内存消耗（used_memory 图）。

「缓存管理」Tab：应用缓存名前缀列表 → 键名列表 → 缓存内容（读值）；删除支持按缓存名、按单个键、清空全部（高危操作，均写操作日志）。

**Redis 通用键空间浏览（只读）**：逻辑库列表（INFO keyspace）→ SCAN 分页（pattern/cursor/count≤500）→ 单键详情（按类型取值：string/hash/list/set/zset/stream）。安全设计：

- 敏感键名（正则命中 token|secret|password|passwd|session|credential|api_key|authorization|refresh）**值一律脱敏**，仅回类型/TTL/大小；
- 单值限量（文本 4000 字符、集合 200 元素、stream 50 条）并标记 truncated；
- 跨库浏览新建短生命周期客户端，用完即关，不污染共享连接池。

权限码：`module_monitor:cache:query` / `module_monitor:cache:detail`（读值）/ `module_monitor:cache:delete`（清缓存）。

## 健康检查（/monitor/health）

- `GET /monitor/health/check`：实时探测 DB / Redis 网络连通，返回 `{db_status, redis_status}` 与「系统健康-{版本}」消息。
- `GET /monitor/health/stream`：SSE 实时流，每 30s 探测一次推送一帧。
- 首页/登录页也可看到健康状态提示。
