# 05 运维与开发

运维管理包含 SSH 运维、SQL 控制台（`/ops/*`），代码管理包含代码生成（`/generator/*`），接口管理为 Swagger 文档（`/swagger/docs`）。这些是**高危模块**：改动或使用时必须保留并覆盖既有校验（AGENTS.md 第 4 章）。

## SSH 运维（/ops/ssh）

### 主机与命令片段

- `ops_ssh_host`：name（唯一）、host、port（默认 22）、username、`auth_type: password|key`、status（0 启用 1 停用）、description。
- **密码 / 私钥 / 私钥口令均以 Fernet（CryptoUtil）加密存 Text 列**；出参永不返回凭据，只给 `has_password`/`has_private_key` 布尔；更新时凭据字段不传视为不修改。
- `ops_ssh_snippet`：常用命令片段（name，command ≤4000 字符，description），供批量执行页快速引用。
- 连接安全：`AutoAddPolicy`、`look_for_keys=False`、`allow_agent=False`——**禁用 SSH agent 与默认密钥**，必须显式提供密码或私钥；私钥支持 Ed25519/RSA/ECDSA，口令可选；连接超时 8s。

### 终端会话（POST 轮询，非 WebSocket）

设计取舍（源码 docstring）：Web 端已有一条 AI 聊天 WebSocket，避免再开一条；局域网延迟下长轮询完全够用，与上游 FastHub 同一做法。

- 端点：`POST /ops/ssh/terminal/open`、`POST /ops/ssh/log/open`（日志跟踪，等价 `tail -n {lines} -F -- {path}`）、`GET /ops/ssh/terminal/{session_id}/poll`（长轮询，timeout 0-5s 默认 2s）、`POST /ops/ssh/terminal/{id}/input`（base64 输入，Ctrl+C 前端转 `\x03` 字节）、`POST /ops/ssh/terminal/{id}/resize`、`POST /ops/ssh/terminal/{id}/resync`、`DELETE /ops/ssh/terminal/{id}`。
- 会话为进程内 `TerminalManager` 内存表（非 Redis），隐含单进程假设；每个会话有读取线程把通道输出灌入队列，`poll` 阻塞最多 timeout 秒取积压数据。
- 前端每 700ms 轮询一次、单次超时 1.2s；窗口尺寸变化 debounce 300ms 后同步 cols/rows；会话关闭即停轮询。
- **配额与回收**：每用户最多 3 个并发会话、全局最多 50 个；空闲 30 分钟回收（`IDLE_TIMEOUT`）；会话归属校验（非本人 403）。

### 批量执行

- `POST /ops/ssh/batch-exec`：host_ids 1-50 台、命令 ≤2000 字符（禁止空字节）、单机超时 1-120s 默认 15s；**并发 5**（信号量）。
- 单机失败不影响其它主机，逐台返回 `{host_id, ok, exit_status, stdout, stderr, error, elapsed_ms}`；输出截断 4000 字符。
- 审计：批量执行写操作日志，记录用户 / 主机 / 命令前 200 字；批量与终端都要求主机 status==0（启用）。

权限码：

| 资源 | 权限码 |
| --- | --- |
| 主机 CRUD / 查询 | `module_ops:ssh:query/create/update/delete` |
| 终端会话（含日志跟踪） | `module_ops:ssh:terminal` |
| 批量执行 | `module_ops:ssh:exec` |
| 命令片段 | `module_ops:snippet:query/create/update/delete` |

## SQL 控制台（/ops/dbconsole）

### 连接管理

`dbconsole_connection`：name（唯一）、`db_type: mysql|postgres`（**仅这两种外部数据库，不提供本地库直连**）、host/port/username/password（**Fernet 加密**）、database、status、description；驱动 `mysql+aiomysql` / `postgresql+asyncpg`。

端点（`/ops/dbconsole/connection/...`）：

- 连接 CRUD：`/list`、`/detail/{id}`、`/create`、`/update/{id}`、`/delete`；
- 测试：`POST /test`（按填写中凭据即时联通，不落库，对应 `conn:update`）、`POST /test/{id}`（测试已保存连接，密码留空回退已存密码，对应 `conn:query`）；
- 库表：`GET /{id}/databases`、`GET /{id}/tables`（库/schema 选择树）；`POST /{id}/query` 执行 SQL——三者均要求 `module_ops:dbconsole:query:execute`。
- 出参不含密码，仅 `has_password`。

### SQL 执行双路径

- **只读路径**：`is_read_only` 预判 + `assert_read_only` 强校验；连接**从不 commit**（写操作即使绕过校验也会随连接关闭回滚）。
  - `READ_KEYWORDS = {select, show, describe, desc, explain, pragma, with, table, values}`；
  - 正则拒绝写关键字 `(insert|update|delete|merge|replace|drop|alter|truncate|create|rename|grant|revoke)`、`into\s*(outfile|dumpfile)`（导出）、`(sleep|pg_sleep|benchmark)\s*\(`（延时探测）。
- **写路径**：前端必须打开「允许写操作」开关（`confirmed=true`，页面上是 ElSwitch），否则报「写操作需要先确认」；且**必须单条语句**，执行后显式 commit 并返回 rowcount。

### 结果处理与安全

- 超时 30s；最多返回 **200 行**（超出标记 `truncated`）。
- **敏感列自动打码**：列名匹配 `(password|passwd|pwd|secret|token|api[_-]?key|private[_-]?key|credential|salt)` 时值替换为 `••••••`，返回 `masked_columns` 供前端黄标提示。
- 前端：结果区标签区分「只读查询 / 写操作」、掩码列黄标、截断行提示、查询耗时与行数、支持结果导出 CSV；`Ctrl+Enter` 快捷执行。
- 查询历史在页面本地维护，可回放。

权限码：`module_ops:dbconsole:conn:query/create/update/delete`（连接管理）+ `module_ops:dbconsole:query:execute`（SQL 执行）。

## 代码生成（/generator/gencode）

### 流程

列表页（FaSearchBar + 操作区 创建/导入/批量删除/批量生成）→ 三步抽屉：

1. **基本信息**：可选上级目录、包名（自动补 `module_` 前缀）、表名；
2. **字段配置**：列编辑 + dict/html/query 复用保留；
3. **代码预览**：`preview_scope: all|frontend|backend` 按文件名高亮，实时渲染**不落盘**。

落盘形态二选一：

- 单表「生成到路径」`POST /generator/gencode/output/{table_name}`：直接写仓库（`backend/app/plugin/{package_name}/{module_name}/` + 前端 `src/api/...`、`views/...`）；
- 多表「批量生成」`PATCH /generator/gencode/batch/output`：打包 `code.zip` 下载（部分失败时 `X-Skipped-Tables` 头提示跳过表）。

生成内容（10 个 Jinja2 模板）：后端 `model.py / schema.py / crud.py / service.py / controller.py / __init__.py` + 包级 `__init__.py` + `plugin.toml`（插件清单，`app/plugin/**` 启动时被 `core/discover.py` 自动扫描注册）；前端 `index.vue` + `api/*.ts`；主子表时子表额外生成 model/schema/__init__ 三个模板。

### 菜单与权限自动生成

代码成功落盘后才创建菜单（模块目录 type=1 + 功能菜单 type=2 + **9 个按钮权限 type=3**：`query/detail/create/update/delete/patch/export/import/download`），权限前缀 `{package_name}:{module_name}`——避免孤儿菜单。

### 安全闸门（三重防线）

1. **渲染层转义**（模板 autoescape=False，按上下文逐类转义）：自由文本字段（table_name/comment/业务名/列注释/dict_type 等）转 `\uXXXX`；标识符经 `safe_ident`（`^[A-Za-z_][A-Za-z0-9_]*$`、≤64、保留字过滤）；Vue 文本剔除 `<>{}` 并 HTML 实体转义；`$` 打断 JS 插值。
2. **哨兵渲染比对**：以不含敏感字符的哨兵渲染出「规范结构骨架」再渲染真实内容；Python 产物要求 ast 解析合法且与骨架 AST 结构一致（`assert_python_structure`），Vue/TS/Toml 逐行结构比对（行数必须一致），不一致即抛「疑似注入」拒绝写入。
3. **落盘路径约束**：写入前校验 `full_path.resolve()` 必须在仓库根内（防路径穿越）；再写受控的 Alembic 空迁移（rev_id=`gen_{table}` 截断 32，多 head 时报错不让自动生成）。

> 风险声明（源码 docstring）：产物写进仓库且会被自动加载，**有代码生成权限 ≈ 任意代码执行**——schema 白名单 + 渲染转义 + 哨兵骨架比对是唯二防线，改动不可放宽。已知上游遗留不一致：Jinja2 模板常量 `FRONTEND_PROJECT_PATH="frontend/web"` 与仓库实际前端目录 `front-web` 不符，生成器写盘路径可能落到仓库内不存在的 `frontend/` 目录（AGENTS.md 已声明仓库存在此类上游遗留，命令与路径以 AGENTS.md 为准）。

权限码：

| 资源 | 权限码 |
| --- | --- |
| 业务表列表/详情 | `module_generator:gencode:query`（详情接口复用查询权限） |
| 创建表结构 / 编辑 / 删除 | `module_generator:gencode:create` / `:update` / `:delete` |
| 数据库表列表 | `module_generator:dblist:query` |
| 导入表结构 | `module_generator:gencode:import` |
| 批量生成 / 生成到路径 | `module_generator:gencode:operate` / `:code` |
| 同步数据库 / 差异预览 | `module_generator:db:sync` |

## 接口文档（/swagger/docs）

- 菜单类型 4（外链）+ `is_iframe=true`，iframe 直载 `VITE_APP_BASE_API + "/docs"`（FastAPI Swagger UI）。
- F5 刷新时链接从 sessionStorage（IframeRouteManager）恢复；也可用菜单的 `meta.link` 覆盖地址。
- 所有接口均需登录后携带 `Authorization: Bearer <access_token>`；Swagger 页右上角 Authorize 内填入令牌即可在线调试。
