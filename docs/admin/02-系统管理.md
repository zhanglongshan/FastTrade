# 02 系统管理

系统管理包含 11 个页面：菜单、字典、参数、部门、岗位、角色、用户、日志、公告、工单、版本。公共约定：

- 所有列表页复用 `FaSearchBar`（勾选 `include-audit` 会自动追加创建人/更新人/时间范围筛选）+ `FaTable`/`useTable` 骨架，窄屏自动切卡片列表。
- 删除都是「勾选后批量删除 / 行内单删」，为**物理删除**（接口传 `ids` 列表），无回收站。
- 通用开关状态：**0=启用 1=停用**；仅登录日志（1=成功 2=失败）、工单（0-3）、版本（0=草稿 1=已发布 2=已回滚）为业务枚举。

## 用户管理（/system/user）

维护登录账号及其部门、角色、岗位归属。

- 左栏部门树联动筛选（dept_id），列表支持账号（like）、用户名（like）、状态搜索。
- 操作：新增/编辑/详情/删除、批量删除、批量启用停用（更多菜单）、**重置密码**（独立接口，规则与创建一致）、**Excel 模板下载 + 数据导入**（`user_import_template.xlsx`，支持 update）、**导出 xlsx**。
- 权限码：`module_system:user:query/detail/create/update/delete/patch/export/import/download`。
- 超级管理员行禁止编辑/删除/重置密码（前端 `disabled: row.is_superuser === true` 保护）；删除当前登录用户会清空本地登录态。

## 角色管理（/system/role）

维护角色并为角色分配菜单（含按钮权限码）与数据范围。

- 操作：新增/编辑/详情/删除、批量删除、批量启用停用、导出；**分配权限抽屉**（菜单树勾选 + 数据范围）。
- 数据范围 `data_scope`：1=仅本人、2=本部门及以下、3=全部。
- 权限码：`module_system:role:query/detail/create/update/delete/patch/export/permission`。
- 角色 `id=1` 为**系统默认角色**：分配权限/编辑/删除被前端保护（提示「系统默认角色，不可操作」）。
- 角色变更后前端自动 `refreshPermissions()` 同步本地权限，即时生效。

## 菜单管理（/system/menu）

管理 Web/APP 两端的完整菜单树（`scope` 字段分端，Web 与 APP 独立成树、互不影响）。

类型枚举（1-4）：

| type | 名称 | 必填字段 | 说明 |
| --- | --- | --- | --- |
| 1 | 目录(CATALOG) | 名称/标题/路由路径/**重定向 redirect** | 仅承载路由层级；可挂目录/菜单/外链子级 |
| 2 | 菜单(MENU) | 名称/标题/路由路径/**组件路径 component_path** | 真实页面，`src/views/` 相对路径 + `.vue` 后缀；可下挂按钮 |
| 3 | 按钮(BUTTON) | **权限码 permission** | 无路由；仅能挂在菜单下（父级固定提示） |
| 4 | 外链(EXTLINK) | 外链地址 `link` + `is_iframe` | 无子级 |

表单字段：`name`、`title`、`type`、`parent_id`（目录不可选父级）、`icon`（按钮隐藏）、`route_name`、`route_path`、`component_path`、`permission`（按钮/菜单必填）、`redirect`（目录必填）、`active_path`、`link`、`params`（路由参数 key/value 动态列表）、`scope`、`order`、`status` 及 `hidden/always_show/keep_alive/affix/is_hide_tab/show_badge/show_text_badge` 等开关。

- 权限码：`module_system:menu:query/detail/create/update/delete/patch`。
- 菜单为平台级资源，无用户归属；菜单增删改后前端同样刷新本地权限。

## 部门管理（/system/dept）

维护树形组织架构（树形表格）。

- 新增子部门/编辑/详情/删除、批量删除、批量启用停用、展开/收起；支持部门名称、状态搜索。
- 权限码：`module_system:dept:query/detail/create/update/delete/patch`。
- 部门编码校验「字母开头、字母数字下划线」。

## 岗位管理（/system/position）

维护岗位字典，用户可多选岗位（`sys_user_positions` 多对多）。

- 新增/编辑/详情/删除、批量删除、批量启用停用、导出。
- 权限码：`module_system:position:query/detail/create/update/delete/patch/export`。

## 字典管理（/system/dict）

左侧字典类型 + 右侧字典数据（dict_data）双栏管理。

- 类型：新增/编辑/详情/删除、行内状态 Switch、批量状态变更。
- 数据：新增/编辑/详情/删除、状态 Switch、`is_default` 标记、导出。
- 前端 `permPrefix` 区分两套权限码：`module_system:dict_type:query/detail/create/update/delete/patch` 与 `module_system:dict_data:query/detail/create/update/delete/patch`。
- 字典驱动业务文案：如公告类型下拉选项取字典 `sys_notice_type`（前端只存 dict_value），修改字典会联动所有引用处。

## 参数管理（/system/param）

以分组 Tab 展示系统参数（`sys_param` 表），单字段/整组/全部保存；无列表搜索。

- 分组：品牌（logo_url、favicon、login_bg、sys_name、login_title、login_subtitle、copyright）、网站、外链（help_doc、privacy、clause）、访问控制（ip_white_list、ip_black_list、demo_enable、ip_location_enable、keep_record）、演示环境等。
- 图片上传：Logo/Favicon/登录背景走 `FaUpload`（≤5MB，可裁剪）。
- IP 黑白名单：列表式增删；演示模式与该两名单在**请求级中间件**生效（见 [07-权限与安全](./07-权限与安全.md)）。
- 权限码：页面级按钮挂 `module_system:param:update`，整体受菜单权限控制。
- 保存后重置全局 configStore 并重新拉取，多端（Web 登录页页脚版权、备案、帮助链接等）即时生效。

## 公告管理（/system/notice）

面向全体用户的公告/通知（富文本编辑器）。

- 新增/编辑/详情/删除、批量删除、批量启用停用；类型来自字典 `sys_notice_type`（1=通知 2=公告）；创建人支持用户选择器。
- 权限码：`module_system:notice:query/detail/create/update/delete/patch`。

## 工单管理（/system/ticket）

卡片式的问题/建议/缺陷工单 + 评论闭环。

- 提交工单（类型 suggestion/bug/optimize/other）、处理（改状态 + 回复富文本）、关闭、删除、批量删除；详情内评论区发表/查看评论。
- 状态机：0=待处理 1=处理中 2=已完成 3=已关闭。
- 权限码：`module_system:ticket:query/detail/create/update/delete/export` + 评论类权限。

## 版本管理（/system/version/list）

发布系统版本更新日志（富文本）。

- 新增/编辑/详情/删除 + 独立「变更状态」弹窗：0=草稿 1=已发布 2=已回滚；删除提示「此操作不可恢复」。
- 权限码：`module_system:version:query/detail/create/update/delete`。

## 日志管理（/system/log）

双 Tab：操作日志 + 登录日志。详见 [03-日志与监控](./03-日志与监控.md)。

## 用户-角色-菜单-权限码 数据关系

关联表（联合主键、CASCADE 级联）：

- `sys_user_roles`（user_id ↔ role_id）、`sys_user_positions`（user_id ↔ position_id）—— 用户/角色、用户/岗位多对多；
- `sys_role_menus`（role_id ↔ menu_id）—— 角色/菜单多对多，权限的载体；
- `sys_role_depts`（role_id ↔ dept_id）—— 角色数据权限的部门维度（模型注释提到 data_scope=5 自定义时使用；当前 schema 限定 1-3、前端未暴露，实际走内置数据范围）。

权限聚合链路（登录时在 `auth/service.py::_collect_permissions` 计算）：

1. 非超管用户 → 遍历其所有**启用中**的角色；
2. 每个角色 → 遍历其关联的**启用中**的菜单；
3. 收集菜单 `permission` 字段为权限码列表（按钮 type=3 的 `permission` 即权限码）。

即：**权限码本质是挂在菜单上的 `permission` 字段**，经「用户→角色→菜单」两级聚合而来。超管（`is_superuser=true`）登录时不收集角色权限，后端校验直接放行、前端天然全量。
