# 04 定时任务与存储

## 定时任务（任务管理 → 定时任务）

### 调度器监控（/task/cronjob/job）

APScheduler 调度器总览页。顶部为状态卡片：

- **状态**：停止 / 运行中 / 暂停；**是否运行中**、**任务数**。
- 可视化 `code_exec_enabled`（代码执行开关是否开启）与「不可调度任务数」（`unschedulable_count`）。

按钮组（均需 `module_task:cronjob:job:scheduler` 权限）：**启动**（仅停止状态可点）、**暂停**、**恢复**（仅暂停可点）、**关闭**（shutdown）；另有**清空所有任务**（`job:task`）与**控制台**（`job:query`，用 `vue-web-terminal` 展示 `scheduler.print_jobs()` 输出）。

**多 worker 选主**：`ap_scheduler.py` 用 Redis 分布式锁 `fasttrade:scheduler:lock`（TTL 30s、续期间隔 10s、争抢间隔 5s），只有持锁进程真正运行调度器，崩溃后候选进程自动接管——避免多副本重复调度。

任务卡片级操作（权限 `module_task:cronjob:job:task`）：暂停 / 恢复 / **调试（立即执行一次）** / 编辑（仅 name / coalesce / max_instances）/ 移除。立即执行通过临时 job `{id}_run_now_{ts}` 实现，不修改原 trigger，执行结束自动移除。

**执行日志**：抽屉内分页表格（`job:query` / `job:detail` / `job:delete`），记录 job_id（手动执行归一为节点 id）、触发类型、状态（0 待执行 1 执行中 2 成功 3 失败 4 超时 5 已取消）、结果、错误（常见失败模式被翻译成中文结论）、job_state（pickle 脱敏序列化的任务元数据）。

### 节点管理（/task/cronjob/node）

「节点」= 一个定时任务定义（DB 表 `task_cornjob_node`），本质是「handler 函数 + 调度计划」的封装，不是分布式 worker 节点。

关键字段：name、code、jobstore（Redis / SQLAlchemy / memory）、executor（AsyncIO 事件循环 / threadpool / processpool）、trigger（cron / interval / date，**空 = 不排程只保存定义，可手动执行**）、trigger_args（Cron 表达式「秒 分 时 日 月 周 [年]」、interval「秒 分 时 天 周」、date「YYYY-MM-DD HH:MM:SS」）、**func（代码块或 builtin 引用）**、args（逗号分隔位置参数）、kwargs（JSON）、coalesce、max_instances、start/end_date、status（0 启用 1 停用）。

**保存即注册**：创建/编辑节点（配置了 trigger）即同步注册/刷新 APScheduler 任务（job id = 节点 id）；停用/删除/取消计划即反注册。启动时 `reconcile_node_jobs` 以 DB 表为真源自愈（补注册缺失、清理残留、刷新 func）。

**可调度性**：页面显示 `schedulable` / `unschedulable_reason`。导致「已启用但不会执行」的原因：未配置 func、**代码块但 `SCHEDULER_ALLOW_CODE_EXEC=false`**、builtin 引用解析失败（模块/函数不存在）、Cron 表达式非法等。

**节点类型**（`handlers/` 目录，内置函数型 = `func: "builtin:<模块名>[.<函数名>]"`，**不经 exec**，不受代码执行开关限制）：

| builtin 引用 | 函数 | 说明 |
| --- | --- | --- |
| `builtin:demo_handler` | `demo_handler(*args, **kwargs)` | 示例函数 |
| `builtin:demo_handler.process_data` | `process_data(data, operation="sum")` | 对 list 聚合 sum/avg/max/min/count |
| `builtin:system_log.cleanup_expired_logs` | `cleanup_expired_logs(days=90)` | 物理清理过期操作日志/登录日志（见 [03-日志与监控](./03-日志与监控.md)） |

builtin 安全边界（`resolve_builtin_handler`）：名称须匹配 `^[a-z_][a-z0-9_]*(\.[a-z_][a-z0-9_]*)?$`；函数必须是**本模块内定义**或经模块 `HANDLERS` 字典显式声明，防 `from os import system` 之类导入绕过开关；解析失败**绝不回退 exec**。

### 代码执行开关 SCHEDULER_ALLOW_CODE_EXEC

`SCHEDULER_ALLOW_CODE_EXEC: bool = False`（等同远程代码执行能力，**默认关闭**；`.env.example` 有升级说明，提示默认已由 true 改为 false）。

影响面：

1. 代码块型任务：开关关闭时**注册被拒、手动执行报错、运行时直接失败**（明确文案 + 日志写入执行日志，不是静默跳过）；
2. builtin 内置函数型：不受影响，开关关闭也正常调度；
3. 页面调度器状态卡片 / 节点列表 / 启动自愈日志都会标出「已注册但不可执行」的任务（包含修复建议：改用 `builtin:` 写法）。

执行方式：代码块在独立 `types.ModuleType` 中用 `exec` 运行，必须定义 `handler(*args, **kwargs)`，运行在 ThreadPoolExecutor。

权限码：

| 资源 | 权限码 |
| --- | --- |
| 调度器监控-查询/详情 | `module_task:cronjob:job:query` / `:detail` |
| 调度器启停/暂停/恢复/关闭 | `module_task:cronjob:job:scheduler` |
| 任务操作（暂停恢复/调试/编辑/移除/清空） | `module_task:cronjob:job:task` / `:delete` |
| 节点 CRUD + 启停 | `module_task:cronjob:node:query/detail/create/update/delete` |
| 节点手动执行 | `module_task:cronjob:node:execute` |

## 存储管理（任务管理 → 存储管理）

### 支持的存储协议

`StorageProtocol` 枚举：**FTP、FTPS、SFTP、S3、OBS、OSS、COS、LOCAL** 共 8 种。分类：

- 对象存储类（S3/OSS/COS/OBS）：bucket + endpoint + region + path_prefix；
- 文件系统类（FTP/FTPS/SFTP/LOCAL）：host + port + 路径。

默认端口：FTP 21 / FTPS 990 / SFTP 22 / S3·OBS·OSS·COS 443 / LOCAL 0。FTPS 复用 FTP 适配器，`is_secure`/`implicit_tls`/`encrypt_type` 区分显式/隐式 TLS；连接模式支持主动/被动；编码 UTF-8/GBK。

### 存储节点（/task/storage/node）

存储源（连接）配置 CRUD + 连接测试 + 详情 + **配置导出/导入**（导出**不含凭据**，导入后需重填密码，按名称去重跳过）。

| 分组 | 字段 |
| --- | --- |
| 基础 | name、protocol、host、port、username、password、bucket、endpoint、region、path_prefix、description |
| 安全/传输 | is_secure、implicit_tls、encrypt_type（0 明文/1 显式 TLS 可用/2 要求显式 TLS/3 隐式 TLS）、connection_mode、encoding |
| 分片上传 | multipart_part_size（默认 50MB）、multipart_concurrency（默认 6）、multipart_memory_budget（默认 512MB） |
| 其他 | advanced_config（JSON，SDK 高级配置，前端按协议动态渲染字段）、is_default（唯一默认源）、status |

- 密码/SecretKey 经 **CryptoUtil（Fernet）加密落库**，接口只回 `has_password` 布尔；测试连接表单密码留空且带 node_id 时回退已保存密码。
- 分页查询 `/storage/node/page`、列表 `/storage/node/list`、协议定义 `/storage/node/protocols`、高级字段 `/storage/node/advanced-fields`。
- 权限码：`module_task:storage:node:query`（含测试/导出）/ `:create`（含导入）/ `:update` / `:delete`。

### 文件浏览（/task/storage/browse）

左节点栏 + 右侧多标签工作区（默认节点固定不可关）。

操作：**上传**（多选 + 队列浮动进度卡 + 拖拽）、**下载**（单文件/多选；**目录递归打包 ZIP** 后下载）、**新建目录**、**重命名**、**复制/移动**（文件级接口；**选中目录走「传输到」通道**——弹窗选目标存储源 + 目录，逐个创建 parallel 传输任务）、**删除**、**分享**（仅对象存储：预签名 URL，有效期 60s~7天可选，复制到剪贴板、过期提示）、多桶切换（对象存储 list buckets / create bucket）、游标分页（page_size ≤ 500）。

路径约束：远端路径防路径穿越；上传/下载/目录打包均经服务端临时文件并在响应后清理。

权限码：`module_task:storage:browse:query`（列表/分享，分享端点挂在 `browse:query` 下）/ `:upload` / `:download` / `:update`（复制/移动/重命名/建目录/建桶）/ `:delete`。

### 传输流程（/task/storage/workflow）

**VueFlow 画布 + 连线（edge）驱动的数据传输编排**：左栏源节点 → 右栏目标节点，支持 1 对多 / 多对 1 / 链式（执行时按每条连线展开成独立传输任务，不是严格 DAG）。

数据职责分离：

- `flow.graph`：仅画布布局（节点位置、连线样式/动画）；
- `flow_node`：业务配置（存储源 + 默认源目录）；
- `flow_edge`：连线启用、传输方式（stream/multipart）、分片参数。

保存需至少一条连线；执行 `POST /storage/workflow/execute/{id}` 按每条连线生成一个 parallel 传输任务，源路径映射 `source_paths: {源存储源ID: 路径}`，无映射则用节点默认目录；目标目录取目标节点默认源目录。

权限码：`module_task:storage:flow:query/create/update/delete`；execute 复用传输创建权限 `module_task:storage:transfer:create`。

### 传输任务（/task/storage/transfer）

- 任务类型：**parallel（多目标）** 单源依次输出到多目标；**chain（链式）** 上一步目标端点是下一步源，链条长度不限。
- 源类型：local（「本地上传」表单，保存到服务端临时文件，执行完自动清理）/ remote。
- 传输方式：stream（流式）/ multipart（分片），支持按任务覆盖存储源的分片大小/并发。
- **SSE 进度**：后台任务独立 DB 会话运行，进度按步骤粒度（运行时显示流动态 50，完成置 100）实时写 DB 并推送；`GET /task/storage/transfer/stream` 为 EventSourceResponse，**令牌走 Authorization 头不进 URL**，按创建者（created_id）隔离推送（只收自己的任务进度）；SSE 抖动/断连不影响传输流水线（广播尽力而为）。
- 状态机：pending / running / success / failed / canceled；取消为内存标志、当前步骤结束后生效。

权限码：`module_task:storage:transfer:create`（含流程 execute）/ `:query` / `:update`（取消）/ `:delete`；SSE 端点仅要求登录态。
