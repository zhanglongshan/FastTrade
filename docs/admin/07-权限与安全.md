# 07 权限与安全

## 权限链路

**权限码 = 菜单（type=3 按钮）上的 `permission` 字段**，经「用户 → 角色 → 菜单」两级多对多聚合（登录时 `auth/service.py::_collect_permissions`）：

```text
用户 (sys_user)
  └─ sys_user_roles ──> 角色 (sys_role)          # 仅遍历启用中角色
       └─ sys_role_menus ──> 菜单 (sys_menu)     # 仅遍历启用中菜单
            └─ menu.permission ──> 权限码列表
```

- 前端按钮：`checkPerm` / `perm-*` / `v-hasPerm`；后端接口：`Security(AuthPermission([...]))`，**两侧使用完全相同的权限码字符串**。
- 超管（`is_superuser=true`）：登录时不收集角色权限，后端校验直接放行，天然全量；前端对超管行禁用编辑/删除/重置密码。
- 角色 `id=1` 为系统默认角色，分配权限/编辑/删除被前端保护。
- 权限变更即时生效：角色/菜单增删改后前端自动 `refreshPermissions()` 同步本地。

## 安全机制总览

### 凭据与密钥

| 位置 | 处理方式 |
| --- | --- |
| SSH 密码/私钥/口令 | Fernet（CryptoUtil）加密落库，出参仅 `has_password`/`has_private_key` |
| dbconsole 连接密码 | Fernet 加密落库，出参仅 `has_password` |
| 存储节点密码/SecretKey | Fernet 加密落库，导出配置不含凭据 |
| SQL / 存储源测试连接 | 表单凭据不落库即时联通；密码留空回退已存密码 |
| 模型 API Key | 按用户隔离存 Redis，接口不回传明文 |
| 币安密钥（量化） | Fernet 加密落库，任何接口不回传明文 |

`.env.dev` / `.env.prod` 等敏感环境文件严禁提交仓库；`SECRET_KEY` 默认值是开发值，生产必须以环境变量覆盖；`DATA_ENCRYPTION_KEY` 未配置时由 SECRET_KEY 经 HKDF 派生。

### 高危能力边界

| 能力 | 默认状态 | 边界 |
| --- | --- | --- |
| 定时任务代码块执行 | **关闭**（`SCHEDULER_ALLOW_CODE_EXEC=false`） | 开启后拥有节点创建/编辑权限者 = 远程代码执行；建议保持关闭、优先用 `builtin:` 内置处理器；内置函数名白名单 + 模块归属校验，解析失败绝不回退 exec |
| SQL 控制台 | 仅外部 MySQL/PostgreSQL | 只读校验 + `confirmed` 写确认 + 单语句 + 30s 超时 + 200 行上限 + 敏感列打码 + 拒绝延时函数/into outfile |
| SSH 终端 | POST 轮询 | 禁用 agent 与默认密钥；每用户 3/全局 50 会话；空闲 30 分钟回收；会话归属校验；批量执行并发 5、输出截断 |
| 代码生成 | 落盘前预览 | 渲染转义 + 哨兵骨架比对 + 仓库根路径约束；产物会被启动时自动加载（≈任意代码执行） |
| 文件上传下载 | 类型受限 | 上传类型 file/avatar/param/resource；路径约束防穿越；下载临时文件响应后删除 |

### 请求级防护

- **操作日志自动采集**：`OperationLogRoute` 自动记录请求/响应，敏感键（password/token/authorization/api_key/secret 等）递归脱敏为 `******`，超长请求体截断；记录范围受 `OPERATION_RECORD_METHOD` 控制。
- **演示模式**：`demo_enable` 参数为 true 时，非 GET 请求（IP 不在白名单且路径不在 `WHITE_API_LIST_PATH`）被中间件拦截返回「演示环境，禁止操作」；IP 白/黑名单同为参数配置，GET 不受限。
- **登录限流**：`LOGIN_RATE_LIMIT_MAX_ATTEMPTS=10` / 60s（Redis 固定窗口，Redis 异常放行）。
- **登录审计**：成功/失败均写登录日志；忘记密码接口不暴露账号是否存在（防用户枚举）。
- **Token 安全**：双 JWT 12h + 滑动续期 + 轮换 + 重放检测（整会话撤销）+ 7 天会话上限；OAuth state TTL 600s、回跳域名白名单。

### 调度集群一致性

多 worker 部署依赖 Redis 分布式锁（`fasttrade:scheduler:lock`）保证单实例调度，防重复执行；调度锁/任务存储均依赖 Redis，Redis 不可用时应评估调度失效影响。

## 部署注意事项

1. **生产环境**：设置强随机 `SECRET_KEY`、`DATA_ENCRYPTION_KEY`；按需放开 `PROD_CORS_ORIGINS`（默认拒绝跨域，`CORS_STRICT_STARTUP` 开启时同源不符直接拒绝启动）；配置 `ALLOWED_HOSTS` / `ALLOW_LOCALHOST_HOSTS`。
2. **升级影响**（`.env.example` 升级说明）：`SCHEDULER_ALLOW_CODE_EXEC` 默认由 true 改为 false——升级后所有代码块型节点不再被调度/执行，健康检查新增 `code_exec_enabled` 字段可确认生效值，节点列表会标出「已注册但不可执行」。
3. **Redis 访问控制**：会话、缓存、模型配置、调度锁都在 Redis；生产应设置密码并限制来源，避免模型 API Key 泄露。
4. **最小权限**：高危操作（代码执行、代码生成、SQL 写、SSH 批量执行、清除缓存）只授予运维/管理员角色；普通用户授予页面「查询」权限即可。
5. **日志磁盘**：操作/登录日志默认保留 90 天（`cleanup_expired_logs`），定期检查磁盘占用，可通过节点任务调整保留天数。
